## Cross-platform native desktop and visual pass (2026-11-14, WM-800 / WM-800-RELEASE)

No release. v0.2.1 stays the published and latest version; it has a Windows desktop bundle only. Linux x64 and macOS arm64 desktop bundles ship from the next tagged release. Contracts, IPC, storage and oracle fixtures are unchanged. The desktop remains a client of the one per-user daemon that WrongStack and MCP clients use.

Changes:

- Desktop views rebuilt on shared primitives (`apps/desktop/src/app/ui.rs`): semantic status/severity/job/connection tones, centered wrapping empty states, label/value evidence fields (provenance, applicability, record details, maintenance schedule with relative times), single-line copyable paths, tinted banners, underline view tabs with a pending-review count, project rows with root paths, a command palette (views, actions, projects) with a dimmed backdrop, status-bar connection dot and `Kbd` shortcut hints.
- Keyboard: view tabs, project rows, the Commands entry and palette rows are `Button`s again (Tab focus, Enter/Space); the palette focuses its first item, moves with Up/Down and returns focus to the workbench when closed; the workbench takes focus on open so Ctrl/Cmd+K works before any click; Review supports Up/Down selection like the library. Found by the runtime pass: shortcuts did nothing until a click, and after any palette choice focus was left on a removed element. A `.hover()` on a GPUI Kit `Button` panicked at first render ("hover style already set"); removed. No render-level test covers that class yet.
- Root causes fixed: Key, Activity and Database (and other icons outside GPUI Kit's default embedded set) rendered as empty gaps; the app now embeds them and `every_referenced_icon_is_embedded` fails for any referenced icon without an SVG (red with `Key` removed, green restored). Empty-state text overflowed its panel. The disconnected state showed two banners, a "Read-only" chip (connectivity is not permission) and "no knowledge" for an absent project. At 940×600 the sidebar shrank to 195 px and broke the brand mid-word; the minimum is now 220 px. The status bar kept "Starting the shared service…" after a successful start.
- Windows desktop links with an 8 MiB main-thread stack (`apps/desktop/build.rs`): the unoptimized build overflowed the default 1 MiB stack on the first frame.
- Platform behavior: Cmd shortcuts, an application menu and Cmd+Q on macOS; on Linux the UI font prefers families with static bold faces (Noto Sans, Liberation Sans, DejaVu Sans), because GPUI drew all weights regular from Ubuntu's variable font.
- Packaging (`scripts/desktop/platform.ts`, `package.ts`, `verify.ts`): host-platform ZIP (Windows) or tar.gz (Linux, macOS), platform executable names, per-target license inventory. `collect-licenses.ts` covers the union of the Windows, Linux and macOS dependency graphs (61 supplemented packages; existing texts byte-identical). `verify.ts` drops an inherited PowerShell 7 `PSModulePath` for Windows PowerShell 5.1, which otherwise loads an incompatible Archive module.
- `wrongmemory install --desktop` admits the executables of the platform it runs on and refuses another platform's bundle. `install.sh` supports `WRONGMEMORY_DESKTOP=1` (verified tar.gz, unsafe path and link refusal before extraction) and refuses clearly when the release has no bundle for the platform.
- CI `desktop-unix` (ubuntu-latest, macos-latest) and release `desktop-unix` (ubuntu-22.04, macos-latest; publish depends on it). `install-scripts.yml` tests the refusal against v0.2.1. WM-ADR-014 addendum, plan, READMEs and desktop AGENTS updated.

## Earlier native desktop checkpoint (2026-11-11, WM-800-GPUI / SHELL / REVIEW / OPS / RELEASE)

An optional native Windows workbench is implemented in [apps/desktop](../apps/desktop/README.md). Its independent workspace pins Rust **1.99.1**, GPUI Kit **0.9.1** and its own lockfile. The core remains on Rust **1.93.0**, with unchanged core manifest/lock/toolchain. [WM-ADR-014](plan/adr-014-native-desktop-workspace.md) records this decision: the earlier exact Kit preflight failed on Rust 1.93 (`gpui-pre` 0.3.12 `cold_path`, E0658) and passed on 1.99.1. The [product program](plan/native-desktop-gpui.md) separates implemented scope from future acceptance.

Implemented: resizable three-panel workbench; virtualized server-paged library; text/status search; full-text evidence inspector; revision-checked edit, protected draft/current-server comparison and explicit rebase; candidate decisions; recover/delete confirmation; bounded GPU relations canvas with zoom/pan; public grants and secret-free generic MCP configuration; health/jobs; explicit existing-CLI-backed daemon start. A bounded worker owns authenticated IPC; the desktop has no SQLite dependency or arbitrary method/shell interface. Dropping the desktop client leaves the daemon and other clients running.

Private presentation preferences preserve theme/project/view/status/zoom/panel sizes and unknown optional JSON fields. Invalid/newer/oversized settings are preserved and reported. Drafts, queries, memory text and credentials are not saved in this file. Drafts survive failed/conflicting saves and reconnect discovery, including detached-project discovery; they remain memory-only. A copy-draft action is available. Presentation saves are asynchronous and can lose the last change on immediate process exit. Navigation is blocked while a mutation is pending; uncertain outcomes are reported without automatic retries.

Windows CI and release jobs now gate the independent workspace. The release job packages matching desktop/CLI/daemon versions, then extracts and hashes the package and runs real-daemon tests against the bundled binaries. These are configured workflows, **not hosted CI success**. No commit, push, tag, publication, installed update or external-client configuration change was performed.

**Daemon spawn without handle inheritance (found while testing WM-800).** `std::process::Command` always creates the child with handle inheritance on. ## Performance (WM-010 / WM-604 / WM-605, synthetic)

Command:

```powershell
cargo build --release -p wrongmemoryd -p wrongmemory-bench
target/release/wrongmemory-bench --corpus s --runs 5 --calls 200 --out benchmarks/results/<date>-s.json
```

- Setup: a real daemon over a real named pipe, with a deterministic seeded corpus.
- Ten percent of the memories are session-private to another session and serve as hard negatives.
- Latencies are measured on the client side, so they include IPC.
- The machine is a local Windows 11 developer workstation, not dedicated benchmark hardware.

| M (25,000), after the path fix (`benchmarks/results/2026-11-01-m.json`) | 954 s (inherited, see below) | 18.8 MiB | 1.22 / 2.78 / 4.02 ms | 2.87 / 5.13 / 7.31 ms | 0.24 / 0.45 / 1.36 ms | 1.00 (300 queries) | 0 |

The recall figure comes from a synthetic corpus of code tokens. It is not a quality claim for real tasks.

Findings from the M run:

- **Fixed: the near-duplicate importance window sorted the whole scope.** That made each `remember` O(n), at 6 writes/s at 10k. It is now one ordered index walk per status, merged on the same key, with the same rows and order.
- **Fixed: path lookup was O(n).** There were two causes:
  - The plan walked every memory in importance order and probed `id IN (edges…)` for each row.
  - The symbol arm used the `from_node` range implied by `GLOB 'mem:*'`.

  Now the hit ids are materialized with `idx_edge_to` pinned on every arm (an exact BINARY prefix range replaces the GLOB) and joined to `memories` by primary key. The result is the same rows; the path oracle passes, including symbol anchors.
  - Reproduction on a 25k-row copy: 9.2 ms → 0.013 ms.
  - A first attempt that only split the GLOB did not help (45 ms in the second M run).
  - Re-measured M: 45 ms → 2.87 ms p50 (other builds were running on the machine during the load phase).
- **Inherited baseline cost, kept for parity: the lexical near-duplicate window.** It is `bm25` over an OR of every prefix term with `LIMIT 32`, as in `sqlite-store-remember.ts` at `222d23a`.
  - It scores every row that shares any term, so `remember` slows as lexically overlapping rows grow.
  - About 60 ms per write at 16k in this corpus, where every row shares common words.
  - Changing it would change which rows dedupe considers.
