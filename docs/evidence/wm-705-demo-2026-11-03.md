# WM-705 demonstration, 2026-11-03

The plan's final demonstration (`docs/plan/validation-and-operations.md` §14), run on Windows 11 with downloaded release artifacts in a disposable environment. All data is synthetic. `WRONGSTACK_HOME`, `WRONGMEMORY_HOME`, `LOCALAPPDATA` (install prefix and WrongStack's binary lookup) and `WRONGMEMORY_CONFIG_HOME_OVERRIDE` pointed into a scratch directory. The user's own WrongStack home, WrongMemory data root and daemon were not touched (the live daemon kept running throughout). No grant secret appears below.

## Other findings

- `wrongmemory connect` wrote no `--data-root` when the data root came from `WRONGMEMORY_HOME`, so a client started without that variable would look in `~/.wrongmemory`. Fixed (WM-306).
- On the user's live data root (read-only inspection), two projects that WrongStack registered on first use were held read-only by `server.json` files whose pids no longer ran. Nothing could upgrade such a registration. Fixed in the daemon (WM-107); the live registrations were not changed.
