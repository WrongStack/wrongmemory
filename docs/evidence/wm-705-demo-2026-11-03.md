# WM-705 demonstration, 2026-11-03

The plan's final demonstration (`docs/plan/validation-and-operations.md` §14), run on Windows 11 with downloaded release artifacts in a disposable environment. All data is synthetic. `WRONGSTACK_HOME`, `WRONGMEMORY_HOME`, `LOCALAPPDATA` (install prefix and WrongStack's binary lookup) and `WRONGMEMORY_CONFIG_HOME_OVERRIDE` pointed into a scratch directory. The user's own WrongStack home, WrongMemory data root and daemon were not touched (the live daemon kept running throughout). No grant secret appears below.

## Other findings

- `wrongmemory connect` wrote no `--data-root` when the data root came from `WRONGMEMORY_HOME`, so a client started without that variable would look in `~/.wrongmemory`. Fixed (WM-306).
- On the user's live data root (read-only inspection), two projects that WrongStack registered on first use were held read-only by `server.json` files whose pids no longer ran. Nothing could upgrade such a registration. Fixed in the daemon (WM-107); the live registrations were not changed.

### Step 6, WebUI path: PASS (WrongStack defect found)

**Records.** Local mode wrote:
- a project record `01M6GX4YD0RF5NQ3N8Y962JZYZ`, anchored to `src/config.ts`;
- a session-scoped record `01M6GX59XFVS879X2HE5B25RE9`.

After the handoff, a host session wrote a second session-scoped record, `01M6GXBV5PKX9WQX352T5A9ZPY`, through the daemon. `wstack webui` was then run on the same project, first in `local` mode and then in `wrongmemory` mode. A WebSocket client sent the Memory Manager's messages.

**Ordinary discovery hides session rows in both modes.** These messages never returned either session record:
- `memory.sage.listPage` (query `harbor`);
- `memory.sage.searchBreakdown`;
- `memory.sage.forFile`;
- `memory.sage.graph`.

**The management messages differ between the two modes:**

| Message | local mode (baseline) | wrongmemory mode |
|---|---|---|
| `memory.sage.list` | includes another session's private record | omits it |
| `memory.list` (chat `/memory`) | includes its text | omits it |
| `memory.sage.get <private id>` | returns the record | `Memory "<id>" not found.`, the same 82-byte reply as for a nonexistent id |
| `stats.total` | 2 (counts the private record) | 1 |

WrongMemory applies the plan's WebUI policy here (session data hidden from WebUI discovery). The baseline does not.

**Finding (WrongStack, both modes).** The Memory Manager's ranked search and search links (`/api/memory/search-page`, `/api/memory/resolve/:id`, `/api/memory/search`) answered `503` in local and wrongmemory mode alike. No host passed the memory store to the HTTP server, and this has been the case since the routes were added in 1.0.29. The fix is WrongStack PR WrongStack/WrongStack#432. Its new CLI test boots the real HTTP bridge over a real store and checks three things:
- ranked pages return the project record and omit session rows;
- resolving a session row's id answers exactly like a nonexistent id;
- removing the wiring fails the test.

The PR is **not merged**. The ranked search therefore stays unavailable in released WrongStack in both modes.

### Checkout evidence (WM-INV-14): implemented in 0.1.4, host run NOT RUN

**Daemon (0.1.4).** The new host-only method `project.bindCheckout` binds a connection to a linked worktree. The daemon accepts the binding only when Git's link checks out from both sides. While bound:
- absolute paths inside the worktree resolve to the shared project paths;
- `memory.verify` checks the worktree's files;
- each result is labeled `checkout: {kind: "linkedWorktree", root}`;
- nothing is written back.

Only the main checkout's verification, or hygiene, changes the shared state.

**Adapter.** WrongStack PR WrongStack/WrongStack#433 adds the matching change: the port binds once per connection when its root differs from the project root.

**Tests.**
- **Daemon:** `a_bound_linked_worktree_gets_its_own_evidence_without_changing_shared_state` in `crates/wrongmemoryd/tests/worktree.rs`. Five mutations each fail it: no path rebase, persisting worktree evidence, no label, accepting any directory, and letting a grant bind.
- **Adapter:** a real-daemon test, `wrongmemory-worktree.integration.test.ts`, run against the local 0.1.4 build. It fails when the port does not bind.

**Not yet run.** A WrongStack host session in a worktree running both changes. That needs a WrongStack build containing #433.
