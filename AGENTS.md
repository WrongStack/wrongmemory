# Agent instructions for WrongMemory

Read `docs/plan/README.md` and the documents it links before changing behavior. The plan's invariants (WM-INV-01..16) and ADRs (WM-ADR-001..013) are binding unless an ADR update says otherwise. Current state and gaps: `docs/status.md`.

## Hard rules

- Never open a real user `sage.db` for writing. Development and tests use disposable fixtures or copies. Adopting a live store is a separately requested deployment step with a consistent backup.
- The inspector (`wrongmemory_storage::inspect`) must stay read-only: no initializer, migration, trigger repair, or text-index refresh.
- Never treat client-supplied project, session, role, origin, or `sources[].type` values as authority. Principal, grant, project allowlist and session come from the authenticated connection.
- Hidden and absent records must be indistinguishable (same error code and shape). Apply visibility before LIMIT, counts, or graph expansion.
- No shell execution, regex evaluation, or project-provided scripts for validity checks or anchors.
- Never put the host token or a grant secret in arguments, logs, responses, client configuration, or skill files. Client configs carry only the project ID and grant ID.
- Contract fixtures (`contracts/`, `tests/fixtures/oracle/`) are generated by `scripts/` from a recorded WrongStack baseline. Do not hand-edit them, and do not change a fixture to make a parity test pass; record the difference in `docs/status.md`.
- Do not claim SAGE parity, MCP client certification, or WrongStack integration that is not implemented and tested. Report PASS / FAIL / NOT RUN / UNSUPPORTED separately.
- Pin new dependencies to exact versions in the workspace `Cargo.toml`.

## Checks before reporting work as done

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

Integration tests that spawn the daemon (`crates/wrongmemoryd/tests`, `crates/wrongmemory-cli/tests`) must pass five consecutive runs for changes touching IPC, process lifecycle, or the bridge.

Regenerating the oracle (needs the WrongStack checkout and Bun):

```powershell
bun run baseline:export -- --wrongstack D:/Codebox/PROJECTS/WrongStack
bun run oracle:prepare
bun run oracle:build -- --wrongstack <clean oracle dir printed by oracle:prepare>
```

## Conventions

- Rust edition 2024, toolchain pinned in `rust-toolchain.toml`.
- SQLite work runs on the blocking pool, never on the async reactor. Each project's store mutex is its serialized writer lane.
- Errors crossing IPC use `wrongmemory_contracts::ErrorCode`. Add a code rather than overloading `INTERNAL`.
- Store rewrites of existing records must patch the original JSON object, not re-encode the typed view. The typed view keeps unknown fields through `extra`, but loses the JS `null` vs absent distinction.
- UI text and docs are English.
- Update `docs/status.md` with task IDs, commands, and results at the end of each session.
